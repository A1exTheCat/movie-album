# Movie Album — проектная спецификация

**Назначение:** передать в Codex как единый продуктовый, UX и технический источник истины для последующей реализации.  
**Статус:** готово к передаче; приложение не реализовано.  
**Язык интерфейса:** английский. Локализация на другие языки не входит в первую версию.

## 1. Видение продукта

Movie Album — персональная коллекция фильмов, представленная как открытый бумажный киноальбом. Визуально это сочетание чистого современного интерфейса и тактильной метафоры альбома с бумажными страницами, вкладками и наклейками-постерами. Альбом остаётся удобным веб-приложением: поиск, каталогизация, просмотр сведений и отметка просмотренных фильмов доступны без скрытых жестов.

Постер непросмотренного фильма отображается в чёрно-белом виде. После отметки **Watched** он плавно превращается в цветную наклейку и занимает своё место в альбоме. Сам факт просмотра и пользовательские даты хранятся в собственной базе; подробная метаинформация и изображения поступают из TMDB.

### Продуктовые принципы

1. **Альбом — главный экран и модель взаимодействия.** Навигация помогает листать коллекцию, а не конкурирует с ней.
2. **Никаких неоговорённых сущностей.** В продукт не добавляются Favorites, Watchlist или похожие списки.
3. **Собственная база минимальна.** Сохраняются только `tmdb_id`, `watched`, `added_at`, `watched_at` и технический первичный ключ/служебные поля, необходимые выбранному хранилищу.
4. **Метаданные не копируются в пользовательскую базу.** Название, описание, жанры, режиссёр, дата релиза, рейтинги, постеры и прочие сведения читаются из TMDB через адаптер/кэш приложения.
5. **Анимация не блокирует задачу.** Её можно пропустить; пользователь с `prefers-reduced-motion` получает короткое растворение/смену цвета.

## 2. Объём продукта

### Входит в первую версию

- Открытый альбом с разворотом страниц и 3D-перелистыванием.
- Верхние закладки: **All Movies**, **By Director**, **By Genre**, **By Decade**.
- Динамические боковые подзакладки для выбранного верхнего раздела.
- Поиск фильма по TMDB.
- Добавление и удаление фильма из альбома.
- Модальное окно с информацией о фильме.
- Переключение статуса Watched и анимация постера в цветную наклейку.
- Постраничная/ленивая загрузка изображений, браузерное кеширование и предварительная загрузка следующего разворота.
- Загрузка, пустые состояния, ошибки, доступность с клавиатуры и адаптивные раскладки.

### Не входит без отдельного решения

- Favorites, Watchlist, рейтинги пользователя, обзоры и социальные функции.
- Совместные альбомы, профили, импорт/экспорт, рекомендации и статистические дашборды.
- Загрузка пользовательских постеров.
- Дублирование каталога TMDB в собственной БД.

## 3. Информационная архитектура

```text
Movie Album
├── Album (основной экран)
│   ├── Верхние закладки
│   │   ├── All Movies
│   │   ├── By Director
│   │   ├── By Genre
│   │   └── By Decade
│   ├── Боковые подзакладки (содержимое зависит от верхней закладки)
│   ├── Разворот альбома (2 страницы на широком экране)
│   ├── Поиск
│   ├── Добавление фильма
│   └── Модалка фильма
└── Глобальные системные состояния
    ├── Загрузка / пусто / ошибка / нет результатов
    ├── Нет сети / ограничение TMDB
    └── Настройки доступности движения (системное предпочтение)
```

Маршрут приложения может оставаться одним экраном с состоянием URL (`section`, `subsection`, `page`, `query`, `movieId`) для возможности обновления страницы и обмена ссылкой на текущий вид. Реализация URL — рекомендована, точный роутер определяется после проверки репозитория.

### Модель данных интерфейса

- **AlbumEntry:** `id`, `tmdb_id`, `watched`, `added_at`, `watched_at`.
- **MovieDetails (TMDB DTO):** данные API TMDB, нормализованные только в памяти/кэше сетевого слоя.
- **SectionState:** активная верхняя категория, подкатегория, сортировка, текущий разворот.
- **ModalState:** выбранный `tmdb_id`, источник открытия, состояние загрузки деталей.

Отображение фильма должно переживать отсутствие отдельных полей TMDB: неизвестные значения не показывать как пустые подписи. Сортировка по умолчанию: стабильная и объяснимая (рекомендуется `added_at` по убыванию в All Movies); групповые разделы — по названию группы, фильмы внутри группы — по названию или году. Выбор надо закрепить в UI и тестах реализации.

## 4. Навигация: два уровня

### Уровень 1 — верхние закладки

Постоянно видны в шапке альбома на широком экране. На узких экранах переходят в горизонтально прокручиваемую полосу или компактный селектор с доступным названием текущего раздела.

- **All Movies:** весь каталог; боковые фильтры/подзакладки: **All**, **Watched**, **Unwatched**.
- **By Director:** боковые подзакладки — режиссёры, встречающиеся в коллекции; счётчик фильмов допустим.
- **By Genre:** жанры из метаданных TMDB, присутствующие в коллекции; счётчик допустим.
- **By Decade:** десятилетия релиза, рассчитанные из года релиза TMDB; отображать диапазон (например, 1990s).

Динамические списки сортируются предсказуемо: режиссёры и жанры по алфавиту, десятилетия по убыванию или возрастанию — выбрать единообразно (рекомендуется новые сначала). Скрывать пустые группы. Если верхний раздел пуст, показывать контекстное пустое состояние и действие поиска/добавления.

### Уровень 2 — боковые подзакладки

Вертикальная полоса рядом с альбомом на широком экране; на планшете — горизонтальная полоса; на мобильном — прокручиваемый список/компактное меню. Активная подзакладка заметно выделена, но не меняет верхний раздел. Для длинных списков — собственная прокрутка, видимый фокус, удержание текущего выбора при возврате из модалки.

## 5. Экран и состояния

### 5.1 Основной экран альбома

**Каркас:** фон приложения; верхняя панель с названием/маркой Movie Album, основными действиями поиска и добавления; ряд верхних закладок; область альбома с боковыми подзакладками, корешком и открытым разворотом; ненавязчивая нижняя область с номером страницы и кнопками назад/вперёд.

**Разворот:** две видимые страницы на больших экранах, оформленные как листы с внутренним корешком и мягкой тенью. Постеры выстроены в аккуратную сетку, допускающую небольшое естественное смещение наклеек, но не ухудшающую считывание и кликабельность. Пустые места можно показать как спокойную фактуру страницы, без фиктивных карточек фильмов.

**Карточка-постер:** постер TMDB с корректным `alt`; непросмотренный — grayscale; просмотренный — цветной, с тонким бумажным контуром/тенью и малым визуальным признаком наклейки. Заголовок/год доступны в подписи или при фокусе; действие на постере открывает детали. Кнопка статуса должна иметь доступную подпись и не полагаться только на цвет.

**Состояния:** начальная загрузка; страницы с данными; пустой альбом; пустая выбранная подкатегория; загрузка изображений; частичная недоступность метаданных; ошибка загрузки; переход страниц; активная модалка; ограниченная анимация.

### 5.2 Поиск и добавление

Поиск открывается кнопкой в шапке/клавиатурным фокусом. Поле имеет явную кнопку очистки и debounce. Результат показывает постер, название, год и доступный вспомогательный контекст TMDB. Уже добавленные результаты помечены **In album** и не могут быть добавлены повторно. Нажатие Add создаёт AlbumEntry с `watched=false`, `watched_at=null`, `added_at=now`; после успеха закрывает/сохраняет поиск и показывает фильм в альбоме. Успешное добавление не должно автоматически устанавливать просмотрено.

**Состояния поиска:** пустой запрос с подсказкой; ввод; debounce; загрузка; результаты; нет совпадений; ошибка сети/API; достигнут предел/ограничение; результат уже в альбоме; добавление в процессе; успешное добавление.

### 5.3 Модальное окно деталей фильма

Открывается нажатием/Enter на постере или результате поиска. Содержит постер, название, год, краткое описание, режиссёра, жанры и прочие доступные значимые поля TMDB. Неполные поля скрываются. Внизу — контекстное действие: **Mark as watched / Mark as unwatched**, **Remove from album** (только если фильм уже добавлен), а из поиска — **Add to album**.

Закрытие: кнопка, Escape, клик по затемнённому фону (если не запущено подтверждение разрушительного действия); возврат фокуса в элемент-инициатор. На мобильном модалка становится полноэкранной панелью/нижним листом с вертикальной прокруткой. При удалении требуется короткое подтверждение либо отменяемое уведомление; конкретный паттерн выбрать единообразно и не допускать случайного удаления.

### 5.4 Отметка Watched и удаление

Отметка Watched запускает визуальный переход: постер постепенно насыщается, получает тонкий белый/бумажный контур и тень наклейки, затем слегка «садится» на страницу. Удаление статуса выполняет обратный переход без эффекта отрыва, который можно принять за удаление. Смена статуса сохраняется атомарно: `watched=true` и `watched_at=now`; снятие отметки — `watched=false`, `watched_at=null`. Ошибка записи возвращает прежний вид и сообщает об ошибке.

Удаление из альбома удаляет только пользовательскую запись; TMDB-данные не изменяются. После удаления закрыть модалку либо оставить её в режиме просмотра из каталога — рекомендуемое поведение: закрыть модалку, обновить разворот и показать отменяемое уведомление, если хранилище поддерживает безопасный undo.

### 5.5 Пагинация/перелистывание

Кнопки предыдущей/следующей страницы, кликабельная область края страницы и клавиатурные стрелки (только когда фокус не в поле ввода) меняют разворот. Перетаскивание на сенсорном экране — дополнительный жест, никогда не единственный способ. На границах альбома соответствующая кнопка недоступна; циклическое перелистывание не применять.

## 6. Визуальная система

### Направление

Современная редакционная типографика, чистые панели управления и контрастные действия соединены с тёплой бумагой, деликатной фактурой и глубиной открытого альбома. Эффект — физический, но не ретро-скевоморфный интерфейс: без тяжёлой состаренности, грязных текстур и перегруженных украшений.

### Цветовые токены (стартовая гипотеза)

- `canvas`: тёплый светлый нейтральный (`#F3F0E8` ориентир).
- `paper`: почти белый (`#FBF9F3`).
- `ink`: мягкий почти чёрный (`#252522`).
- `muted`: средний тёплый серый.
- `accent`: глубокий киноварно-красный или бордовый для активных вкладок/основного действия.
- `line`: тонкие бежево-серые разделители.
- `focus`: контрастный синий/системный контур, не совпадающий только с цветом статуса.

Значения — отправная точка; настроить контраст по WCAG AA для текста и интерактивных элементов. Предусмотреть CSS-переменные, тёмную тему не считать обязательной для первого релиза.

### Типографика и формы

- Заголовки альбома/разделов: выразительный serif допустим.
- Интерфейс, кнопки, метаданные: читаемый sans-serif.
- Не использовать декоративный шрифт для мелкого текста.
- Радиусы: небольшие для контролов, почти прямые углы для бумажного листа.
- Тени: несколько мягких слоёв с низкой непрозрачностью; реальная глубина только у корешка, страниц и наклеек.
- Иконки: единый набор, сопровождаемый текстом там, где значение не очевидно.

## 8. Адаптивность

- **Широкий экран (ориентир ≥1200 px):** верхние закладки в строке, вертикальные подзакладки, физический разворот на две страницы, 4–6 постеров на сторону в зависимости от ширины.
- **Планшет (ориентир 768–1199 px):** верхние закладки прокручиваются при нехватке ширины, боковые подзакладки упрощаются до горизонтальной полосы; альбом может оставаться двухстраничным при достаточной ширине либо переключаться на одну страницу.
- **Телефон (<768 px):** одностраничное отображение альбома; верхние закладки горизонтально прокручиваются; подзакладки — в отдельной полосе; постеры в 2–3 колонки; детали занимают экран; действия имеют touch targets около 44×44 CSS px.

Точные пороги определяются фактической сеткой и проверяются на промежуточных размерах. Не допускать горизонтальной прокрутки всего документа. Сохранять одинаковые правила сортировки и смысл групп на всех размерах.

## 9. Движение и обратная связь

- Перелистывание: короткий 3D-поворот страницы вокруг корешка, перспектива сдержанная, тень меняется вместе с углом. Анимация не должна пересобирать DOM всей коллекции.
- Отметка watched: насыщение изображения + эффект наклейки, около 450–700 мс; пользовательская команда и сохранение не ждут завершения визуального эффекта.
- Модалка: fade и небольшой scale/slide, около 160–220 мс.
- Добавление/удаление: короткий feedback в карточке/уведомлении.
- При `prefers-reduced-motion: reduce`: отключить 3D вращение и пространственные перемещения, заменить их быстрым crossfade; вся функциональность остаётся доступной.
- Не запускать тяжёлые анимации одновременно для десятков элементов; анимировать текущую страницу/целевой постер.

## 10. Техническая архитектура для последующей реализации

Репозиторий и стек сейчас отсутствуют, поэтому сначала требуется создать/обнаружить проект и выбрать стек с учётом окружения. Рекомендованная слоистая структура:

```text
src/
  app/                 # entry, маршруты, layout
  features/album/      # страницы, развороты, фильтры
  features/movies/     # поиск, детали, статус, удаление
  components/          # общие UI-компоненты
  services/tmdb/       # клиент TMDB, DTO, нормализация
  services/storage/    # репозиторий AlbumEntry
  hooks/               # загрузка, пагинация, кэш
  styles/              # токены и базовые стили
```

### Хранилище

Таблица `album_entries` (или эквивалент):

| Поле | Тип/ограничение | Назначение |
|---|---|---|
| `id` | первичный ключ | внутренний идентификатор строки |
| `tmdb_id` | integer, unique, not null | связь с фильмом TMDB |
| `watched` | boolean, not null, default false | текущий статус просмотра |
| `added_at` | timestamp, not null | дата добавления пользователем |
| `watched_at` | timestamp, nullable | дата последней отметки просмотрено |

Дополнительные поля с содержимым каталога запрещены без пересмотра решения. Тип timestamp — хранить в UTC, форматировать по локали. Текущее локальное IndexedDB-хранилище должно переносить существующие записи в Supabase при подключении, если облачная таблица ещё пуста.

### Публикация и публичность данных

Фронтенд публикуется как статический сайт через GitHub Pages; данные хранятся в Supabase Free. Приложение работает без входа и аккаунтов. RLS разрешает анонимному `anon` доступ на чтение, добавление, изменение и удаление строк `album_entries`; любой посетитель сайта сможет менять общую коллекцию. В таблице не должно быть персональных или приватных данных. В браузер передаётся только Supabase URL и публичный anon/publishable key; `service_role` key запрещено помещать во фронтенд.

### TMDB и ключ API

Для локального режима допускается прямой вызов TMDB с ключом из `.env.local`. В опубликованном приложении запросы проходят через публичную Supabase Edge Function `tmdb`; TMDB Read Access Token хранится только в секретах Supabase и не включается в сборку GitHub Pages. Function пропускает только нужные маршруты поиска, жанров и деталей. Проект рассчитан на некоммерческое личное использование; если его основной целью станет получение дохода, до такого использования нужно запросить у TMDB коммерческую лицензию.

- Взаимодействовать с TMDB через отдельный клиент, централизованно собирать ошибки и лимиты.
- В Credits/footer показывать неизменённый одобренный логотип TMDB, ссылку на `https://www.themoviedb.org` и точное уведомление: “This product uses the TMDB API but is not endorsed or certified by TMDB.” Логотип не должен быть заметнее бренда Movie Album или создавать впечатление одобрения TMDB.
- Соблюдать текущие требования TMDB к атрибуции и использовать актуальные image configuration/base URL и размеры из API, не зашивать хрупкую сборку URL по всему UI.
- Изображения получать в подходящем размере для устройства; показывать placeholder до загрузки; ошибка изображения не ломает сетку.

### Запросы, кэш, производительность

- Поиск: debounce (ориентир 250–350 мс), отмена предыдущего запроса при новом вводе, минимум символов выбрать в реализации.
- Метаданные деталей кешировать на уровне клиента по `tmdb_id` и учитывать срок актуальности/условия API.
- Постеры: нативный браузерный HTTP cache, корректные cache headers источника, `loading="lazy"`, `decoding="async"`, responsive sizes. Не скачивать коллекцию целиком при открытии.
- Загружать постеры текущего разворота и ближайшего соседнего; использовать `IntersectionObserver`/эквивалент для видимой части. Следующий разворот предварительно загружать с низким приоритетом и отменять/сбрасывать лишние запросы при быстром перелистывании.
- Сохранять выбор раздела/подраздела/страницы при открытии и закрытии деталей.
- Оптимистичная смена watched допустима только с rollback при ошибке записи.
- Сетевая ошибка TMDB не должна блокировать просмотр пользовательских записей; где возможно показать локально сохранённые записи с fallback-карточками без метаданных.

## 11. UX-потоки

### A. Первый запуск и добавление фильма

1. Открыть All Movies.
2. Если альбом пуст, показать объяснение ценности альбома и основное действие **Find a movie**.
3. Открыть поиск, ввести название.
4. Показать загрузку, затем результаты TMDB.
5. Открыть детали результата или сразу Add.
6. Добавить `tmdb_id`; показать подтверждение; поместить непросмотренный постер на текущую страницу.

### B. Изменение статуса просмотра

1. Нажать статус в модалке или доступный контрол у карточки.
2. UI запускает анимацию и оптимистично обновляет цвет.
3. Записать watched и watched_at.
4. При успехе сохранить новое состояние; при ошибке вернуть предыдущее и показать повтор действия.

### C. Найти фильм в коллекции

1. Переключить верхнюю вкладку или воспользоваться поиском по каталогу.
2. В выбранном разделе перейти к динамической боковой подзакладке.
3. Листать альбом кнопками, клавиатурой либо жестом.
4. Открыть детали; закрыть и вернуться на прежний разворот и в ту же группу.

### D. Удаление

1. Открыть детали фильма из альбома.
2. Выбрать Remove from album.
3. Подтвердить или отменить действие.
4. Удалить пользовательскую запись, обновить группу и разворот, показать обратную связь.

## 12. Доступность и качество

- Семантические кнопки/ссылки, корректные заголовки и landmarks.
- Все действия доступны клавиатурой; видимый focus ring.
- Модалка удерживает фокус внутри, закрывается Escape и возвращает фокус инициатору.
- Статус watched передаётся текстом/иконкой, не только цветом/анимацией.
- Контраст текста и контролов WCAG AA; alt для содержательных постеров (название фильма), декоративные текстуры скрыты от screen reader.
- Сенсорный сценарий не требует hover или точного перетаскивания.
- Ошибки и статусы объявляются screen reader через подходящую live region.
- Тестировать пустой альбом, большие коллекции, длинные названия, отсутствующие поля TMDB, плохую сеть, быстрые повторные действия, мобильный viewport и reduced motion.

## 13. План реализации по этапам

### Этап 0 — аудит и фиксация основы

1. Проверить целевой каталог, git-репозиторий, существующий стек, команды запуска и локальные правила.
2. Если проект пуст — выбрать фронтенд-стек и хранилище, затем создать базовый scaffold отдельно от этой спецификации.
3. Согласовать локальный IndexedDB режим и публичную Supabase/GitHub Pages публикацию; не добавлять аккаунты. Зафиксировать правило пагинации и сортировки из этой спецификации.

**Приёмка:** Codex описал найденное состояние проекта, выбранные предположения и архитектурные решения; рабочие файлы и секреты не закоммичены.

### Этап 1 — визуальный каркас и дизайн-токены

3. Реализовать подзакладки для четырёх разделов с тестовыми данными.
4. Сверстать раскрытый альбом, корешок, страницы и сетку постеров.

**Приёмка:** все 4 раздела и вторичная навигация работают на desktop/tablet/mobile; активное состояние понятно; интерфейс не ломается при длинных названиях и пустых группах.

### Этап 2 — модель пользователя и хранилище

1. Создать схему `album_entries` и уникальность `tmdb_id`.
2. Определить интерфейс репозитория и операции list/add/remove/setWatched для IndexedDB и Supabase.
3. Добавить SQL-миграцию и открытые RLS-политики для публичной коллекции.
4. При первом подключении перенести локальные записи в пустую облачную таблицу без повторов по `tmdb_id`.

**Приёмка:** persisted-поля ограничены утверждёнными данными; повторный `tmdb_id` невозможен; даты корректны; локальный и облачный режимы работают; любой посетитель может читать и менять публичную коллекцию; перенос локальных данных не создаёт дублей.

### Этап 3 — TMDB интеграция

2. Подключить поиск, детали, групповые метаданные, постеры и атрибуцию.
3. Обработать загрузку, отсутствие полей, rate limit, сеть и ошибки изображения.

**Приёмка:** поиск и детали показывают актуальные данные TMDB; секрет не попадает в клиентский bundle/репозиторий; в Credits видны одобренный неизменённый логотип, ссылка на TMDB и обязательное уведомление; при ошибках интерфейс объясняет состояние и позволяет повторить.

## 14. Сквозные критерии готовности

- Пользователь может добавить фильм из TMDB, найти его через каждый подходящий способ навигации, открыть детали, отметить watched/unwatched и удалить его.
- Состояние страницы, выбранная категория и подкатегория предсказуемо сохраняются при закрытии модалки.
- Непросмотренный фильм чёрно-белый; просмотренный цветной; анимация доступна и имеет reduced-motion-вариант.
- В собственной БД не сохраняются метаданные/постеры каталога; сохраняются только согласованные пользовательские поля и технический ключ строки.
- Изображения загружаются лениво; текущий и следующий разворот получают приоритет; браузерный cache используется корректно.
- Четыре верхние закладки и динамические боковые подзакладки существуют на всех размерах экрана.
- Приложение не содержит Favorites, Watchlist или сходных незаказанных разделов.

## 15. Согласованные решения и предположения

- Язык интерфейса: английский.
- Без входа и аккаунтов; опубликованная коллекция публична и доступна на чтение/изменение всем посетителям.
- Публикация: GitHub Pages; база: Supabase Free; локальный режим IndexedDB остаётся для разработки и исходных данных.
- TMDB в production: Supabase Edge Function proxy с секретом, настроенным в Supabase.
- Альбом листается последовательными страницами; вместимость подстраивается под адаптивную сетку.
- All Movies сортируется по `added_at` от новых к старым; фильмы в группах — по названию A–Z; группы сортируются по алфавиту, десятилетия — от новых к старым.
- Детали показывают компактный набор: постер, название, год, краткое описание, режиссёр и жанры.

Остаётся выбрать точный размер страницы после реализации адаптивной сетки; он может быть рассчитан из доступного места и количества колонок.
